Gui Ferreira tours Claude Code beyond basic code generation: a lean setup, everyday shortcuts, reusable automation, and personal uses outside programming. His recurring advice is to keep instructions and conversation history focused, make feedback automatic, and tell the agent how to verify success. His final suggestion: run /insights to learn from your own usage.

Source basis

Full timestamped captions through the closing applause at 54:11, supplemented by full-video Gemini viewing notes for on-screen commands. Viewing notes are not a verbatim transcript. Official Claude Code, Obsidian, and Strava pages were independently checked for the resource links below.

Key ideas

Setup once: put instructions in the right place, avoid duplicate rules, protect sensitive files, and make the status line useful. 4:21

Daily workflow: refine plans before coding, undo dead ends, inspect context, and use shortcuts instead of repeatedly explaining the same thing. 13:37

Platform layer: package scripts into skills and use hooks to run checks automatically rather than relying on a reminder in a prompt. 39:33

Beyond code: the same file-reading and automation abilities can organize downloads, summarize work, connect notes, and process activity records. 46:27

Items covered (not ranked)

Import another agent's setup

Use /import with the source tool, such as codex, to bring over configuration rather than recreating it. Ferreira describes importing server connections, skills, and subagents. 4:25

Reuse files instead of copying rules

In CLAUDE.md, import existing files with @RULES.md or @schema.json. His reason: duplicate instructions waste space and can drift apart. 5:59

Keep CLAUDE.md lean

Keep broadly useful rules; move occasional tasks into skills and language-specific rules into .claude/rules/. Remove information the agent can discover from the repository. 7:27

Run /doctor

Ferreira recommends it for installation checks and reviewing overloaded or duplicated project instructions. 8:50

Separate personal and team instructions

Shared project rules belong in CLAUDE.md; personal project preferences in git-ignored CLAUDE.local.md; cross-project preferences in ~/.claude/CLAUDE.md. 9:25

Deny access to sensitive material

Configure permissions.deny in .claude/settings.json for sensitive files and unwanted commands. His warning: debugging can lead the agent to inspect secrets unless access is restricted. 10:35

Customize the display

Use /theme for appearance, then /statusline for a dashboard showing the project, branch, model, and context used. He considers the status line more useful than cosmetic changes. 12:04

Edit the plan directly

Shift+Tab enters Plan Mode; Ctrl+G opens the plan in an editor. Save small corrections there instead of spending several chat turns requesting them. 14:05

Ask Claude to interview you

Request questions until assumptions and tradeoffs are clear. Ferreira prefers discovering missing requirements before implementation. 15:30

Rewind a wrong turn

Use Esc twice or /rewind to return to an earlier point and choose a different direction, rather than carrying a failed approach through the rest of the conversation. 18:00

Change model and effort deliberately

Use /model for model selection and adjust reasoning effort for the task. He notes that planning and implementation do not necessarily need the same effort, even with the same model. 18:35

Use ultrathink for one hard prompt

Ferreira describes it as raising reasoning effort for that turn, then returning to the previous level so you do not forget a lasting change. 19:40

Stash an unfinished prompt

Ctrl+S puts your draft aside so you can answer an interruption, then restores it when pressed again. No notepad needed. 21:01

Ask a side question with /btw

Get an answer while the main task continues, without adding that side discussion to its working conversation. 21:31

Inspect usage

Check usage and model breakdowns, including models used by subagents, rather than assuming only the model you selected contributed to the session. He also likes cost visibility in the status line. 22:17

Check an empty session with /context

Look for instructions, tools, and skills consuming space before you have asked anything. His example of 8% overhead is a reason to investigate, not a universal limit. 23:34

Compact at useful milestones

Use /compact after a major implementation stage when the history still matters, or when repeated failed attempts clutter the conversation. He explicitly calls the proposed 40% context danger zone an opinion, not a proven threshold. 24:40

Audit memories

Use /memory to find false assumptions, remove stale material, and promote genuinely useful recurring rules into CLAUDE.md. His example: an assistant mistakenly adopted a name from an article he asked it to summarize. 26:38

Run known shell commands directly

Prefix a command with !, such as !npm test, when you already know what to run. This avoids asking the model to decide the command, but its output still enters the conversation: do not print secrets. 28:24

Inspect edits with /diff

Open the file-change view inside the terminal instead of switching to another window to see what Claude changed. 29:39

Continue from your phone

Start Remote Control for a long task, then monitor it or answer approval requests through the app away from your desk. Ferreira says this lets him take a walk while implementation runs. 30:23

Dictate with /voice

Enable voice, then hold Space to speak. He finds that explaining a problem aloud clarifies it, but does not recommend dictation in an open office. 32:17

Supply screenshots

Paste or drag an image into the terminal and explain which visual details you want. His Mac shortcut is Ctrl+V, not Cmd+V. 33:37

Separate parallel work

Use Git worktrees for simultaneous feature work, reviews, and bug fixes. Use /color and /rename to identify sessions; his examples are red for bugs, orange for refactoring, and blue for features. 34:35

Define a verifiable /goal

State both the outcome and how to check it, such as a passing test that exercises an API and checks its generated PDF. Ferreira says the agent can then iterate without asking you about every step. 36:21

Reduce noise with /focus

Hide intermediate chatter so returning to a session shows the request and final result more clearly. 37:36

Use the agents overview

Start with claude agents, or use the desktop app, to see which agents are working, finished, or need your attention. 38:46

Automate feedback with hooks

Run tests or a linter after edits through a PostToolUse hook. His reason: checks happen reliably and failures reach Claude before it declares the job done. 39:55

Package real capabilities as skills

A skill can contain Python or PowerShell scripts, references, and instructions, not just a prompt. His example is turning a team's occasionally used troubleshooting scripts into reusable skills. 41:30

Try /batch and /simplify before reinventing them

/batch divides large migrations across agents; /simplify reviews changes for duplication and unnecessary complexity. Ferreira especially likes /simplify. 43:01

Let /loop do repeated checking

His example is /loop 5m check if the deploy finished, replacing manual refreshes of a deployment page. 43:54

Share project connections through .mcp.json

Commit the project's MCP server definitions so colleagues can use and review the same tool connections, instead of relying on setup instructions elsewhere. 44:27

Use headless mode in scripts

claude -p or --print runs a request and exits. Ferreira shows piping information into Claude and sending its answer onward as one step in an existing script. 45:31

Summarize work for reviews

Ask what you have built, then package that retrospective into a skill for recurring reviews rather than reconstructing months of work manually. 47:28

Sort downloads before deciding what to delete

Ferreira had Claude organize 1,626 items into categories, making disposable installers and screenshots easier to distinguish from documents needing human review. 48:37

Work with an Obsidian notes folder

Use Claude on the underlying Markdown files to summarize meetings, surface upcoming obligations, and connect research notes. He values keeping the files usable with other tools too. 50:00

Connect records to a recurring planning skill

His personal example uses one skill to copy Strava runs into Obsidian and another to draft the next week's running plan from that history. This is his anecdote, not evidence of medical safety. 52:01

Finish with /insights

If the talk offered nothing new, Ferreira's fallback recommendation is to inspect how you actually use Claude and where your workflow could improve. 53:44
