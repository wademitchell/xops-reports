Gui's rapid-fire tour treats Claude Code as a customizable assistant, not just a code generator. His recurring advice is to keep instructions lean, manage context deliberately, automate feedback, and use the same tools for everyday files and notes. His closing recommendation: run /insights to learn how you actually use it.

Key ideas

Setup: configure instructions, boundaries, and visibility once. Gui prefers the terminal because he finds it faster and says new experimental features arrive there first. 4:21

Daily workflow: plan collaboratively, undo wrong turns cleanly, and keep track of models, context, and parallel work. 13:40

Platform layer: package repeatable capabilities and make checks run automatically, rather than relying only on reminders in a prompt. 39:33

Beyond code: the same assistant can organize files, summarize accomplishments, and work with a folder of personal notes. 46:27

Items covered (not ranked)

Import an existing setup

/import codex, or the relevant supported tool name, brings configuration such as tool connections and subagents into Claude rather than rebuilding it manually.

Reference files instead of copying them

Use @RULES.md or another @path in CLAUDE.md so existing documentation remains the source of truth.

Keep CLAUDE.md lean

Gui cites a study reporting lower performance and higher cost from overly descriptive instruction files. His three questions: needed for every task? Keep it. Only sometimes? Move it to a skill or .claude/rules/. Discoverable from the project? Remove the duplicate description.

Run /doctor

Gui says it checks installation health and can help clean duplicated or misplaced instructions inside a project.

Separate instruction scopes

Put personal project habits in a Git-ignored CLAUDE.local.md, shared team rules in CLAUDE.md, and truly global preferences in ~/.claude/CLAUDE.md.

Deny access to secrets

In .claude/settings.json, use permissions.deny for sensitive files and unwanted commands. Gui's warning: debugging can otherwise pull secrets into the conversation.

Pick a readable theme

/theme changes Claude's appearance; terminal styling is a separate layer.

Build a useful status line

/statusline can show the Git branch, model, and context usage so you know what session you are in.

Edit the plan directly

Shift+Tab reaches plan mode; Ctrl+G opens the plan in your editor. Save small corrections there instead of negotiating every line in chat.

Ask for an interview

Tell Claude to interview you until unclear choices are resolved, using its question tool rather than silently accepting assumptions.

Rewind a bad direction

Esc twice or /rewind returns to an earlier checkpoint instead of piling a corrective refactor onto the failed attempt's context.

Switch models mid-session

/model lets you choose a stronger model for planning or a cheaper one for execution without starting over.

Adjust effort separately

/effort changes reasoning effort, so model selection is not your only speed-and-cost control.

Boost one difficult prompt

Gui demonstrates ultrathink for maximum effort on one request without leaving the whole conversation at that setting.

Stash an unfinished prompt

Ctrl+S saves the text you are typing so you can answer an interruption; press it again to restore the draft.

Ask a side question

/btw asks while the main task continues, instead of queueing the question behind it.

Inspect usage and cost

Gui shows session statistics to understand which models and tokens were used, including subagents, rather than guessing the cost of a feature.

Check empty-session overhead

Run /context before doing work to see how much space instructions, skills, and tools already consume; remove things you do not need.

Compact at useful boundaries

/compact can summarize history between phases, such as finishing the model before starting the interface. Gui explicitly calls the often-cited 40% context danger threshold an opinion, not a study-proven limit.

Audit memories

/memory helps find false assumptions and useful preferences; delete errors and move genuinely shared rules into the appropriate instruction file.

Run simple shell commands directly

Start with ! for commands you already know, such as ! git status. Gui warns that their output still enters the conversation, so avoid dumping secrets.

Watch changes with /diff

Open the side-by-side change view rather than switching to a separate terminal to inspect edits.

Continue away from the desk

/remote-control lets Gui monitor work and answer approval or clarification requests from his phone. He highlights the freedom to take a walk, while joking about the work-life tradeoff.

Explain a problem aloud

/voice enables speaking while holding Space. Gui finds it helps him reason through problems, but does not recommend dictating in an open office.

Supply screenshots

Paste or drag an image into the terminal when a visual example explains the intended interface better than text. Gui notes Ctrl+V rather than Command+V in his Mac example.

Isolate parallel work

--worktree gives concurrent tasks separate Git working folders, avoiding edits to the same checkout.

Name and color sessions

/rename and /color make it easier to distinguish bug fixes, refactors, and features across tabs.

Give a measurable goal

/goal should state both the desired result and how to verify it, such as a passing test and a correctly generated PDF. Gui says this reduces step-by-step babysitting.

Hide intermediate chatter

/focus keeps the original request and final answer prominent when you do not need every execution update.

View all agents together

Start with claude agents, or use the desktop app, to see who is working, finished, or waiting for your attention.

Automate fast feedback

Use a PostToolUse hook after edits to run tests or a linter and feed failures back to Claude. Gui prefers this to merely writing 'always run tests' in the instructions.

Package skills as capabilities

A skill can include scripts, reference notes, and templates alongside SKILL.md. His example is turning occasional team maintenance scripts into reusable capabilities.

Try the built-in migration skill

/batch divides a large refactor into parallel pieces; the on-screen command is used here because captions transcribe it as 'patch'.

Try /simplify before making another cleanup skill

Gui calls it a favorite for removing duplication and maintainability problems.

Let /loop do repetitive checking

His example checks every five minutes whether a deployment has completed, instead of manually refreshing the build page.

Share project tool configuration

Commit .mcp.json so teammates can discover the project's external tool connections rather than following a separate installation checklist. Do not put credentials in shared configuration.

Use headless mode

claude with --print or -p runs a supplied prompt and exits. Gui shows piping input into it and sending the result to a file as one step in a larger script.

Summarize accomplishments

Ask what you shipped and turn the recap into a reusable review-preparation skill instead of reconstructing months of work manually.

Organize a crowded Downloads folder

Gui had 1,626 items sorted into categories so he could review documents separately from disposable installers and screenshots.

Work with an Obsidian vault

Run the assistant against local Markdown notes to surface deadlines, summarize meetings, and connect research. Gui likes that the files remain portable to other assistants.

Combine a data skill and a planning skill

His personal example pulls Strava runs into Obsidian, then uses that history to structure the next week's running. This is his experience, not evidence of medical safety or a training prescription.

Finish with /insights

Gui's final request is to run it for a report on your own usage patterns, even if the talk taught you nothing else. 53:44 closing recommendation

Caveats
