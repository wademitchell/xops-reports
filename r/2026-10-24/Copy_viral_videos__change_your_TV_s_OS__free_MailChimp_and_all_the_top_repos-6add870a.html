Andrew Warner and Adam tour tools for newsletters, cleaner TV home screens, video editing, and AI-assisted coding. Their central distinction is between useful automation and copying someone else's work or identity: they welcome reusable workflows but question unauthorized voice/face copying and extraction of proprietary software features.

Repository identities were checked on the linked GitHub pages. Time links below use the creator's chapter starts, not exact observed claim timing.

Key ideas

The opening tools tackle everyday annoyances: paying newsletter fees for inactive subscribers, ad-heavy TV interfaces, and repetitive video editing.

Much of the main list helps coding assistants work better: specialized instructions, teams of agents, app controls, and shared project memory rather than just a new chatbot.

The hosts separate copying a video's editing format from copying a person's likeness, and debate whether reverse-engineering paid software crosses a more serious line.

Items covered (not ranked)

Mailcheap

Opening pick: Marc Lou's newsletter platform charges around sending rather than dormant subscriber counts. The hosts highlight self-hosting and agent-controlled drafting/sending as alternatives to conventional newsletter platforms; free software still leaves hosting and email-delivery costs. 00:18

github.com

CleanYourTV

Opening pick: connects to Android/Google TV over Wi-Fi, backs up settings, disables unwanted packages, and installs a cleaner home screen. The appeal is avoiding tedious menus and reducing ads/tracking. This is not a replacement operating system for every smart TV; the workflow uses Android debugging access and reversible package changes. 02:26

github.com

Hypit (called Hypeit in the description)

Opening pick: reconstructs a video's editing structure, captions, cuts, and effects so new content can reuse its format. The hosts distinguish that from using someone else's face or voice without permission, which they reject. 03:41

github.com

REA

Main-list #1: helps agents examine existing applications and reproduce features, including examples involving media players and productivity apps. Adam objects to extracting proprietary implementation work or bypassing paid features, while examining your own software for bugs is a different use. The segment is a debate, not an endorsement of unrestricted copying. 05:29

github.com

Claude Plugins Official

Main-list #2: Anthropic's directory of Claude Code add-ons. The hosts focus on security scanning that looks for exposed secrets and vulnerable code and can help prepare fixes. They present it as useful assistance, not proof that a codebase is safe. 09:19

github.com

Ruflo

Main-list #3: coordinates a team of coding agents with separate planning, implementation, review, and operations roles. The attraction is shared memory and organized delegation rather than asking one general assistant to do everything. 11:21

github.com

Android Skills

Main-list #4: Google's specialized instructions for agents building Android apps. The hosts highlight current platform practices, including on-device AI, to reduce outdated code and poor battery/resource handling. 14:25

github.com

Scientific Agent Skills

Main-list #5: a collection presented as 177 science/research skills, from finding papers to preparing scientific documents. The hosts also recount complaints about instructions promoting the maintainer's paid service, reportedly later removed; that history is their account, not independently established here. 16:48

github.com

OpenCode

Main-list #6: an open-source coding assistant with terminal, desktop, and editor interfaces and a choice of models. Adam likes its flexibility for building customized agent systems. He distinguishes a reported hosted-service security incident from the local client; this summary does not independently verify that incident's scope. 18:12

github.com

CLI-Anything

Main-list #7: gives agents command-based ways to operate applications such as Blender, GIMP, and LibreOffice. The hosts prefer this to slow, brittle screenshot-and-click control when an application can be driven through commands. 20:37

github.com

Cursor Plugins, including pstack and ketchup

Main-list #8: add-ons connect tools and package coding workflows. Their standout is Lauren Tan's pstack; its ketchup skill explains what changed since the user's last message and identifies decisions waiting on them. 23:32

github.com

AI Memory

Main-list #9: preserves project context in shared local notes so different coding assistants can pick up the same work. Adam's motivating example is switching tools or computers without re-explaining decisions and rejected approaches. 25:01

github.com

VoiceStudio

Main-list #10: local voice cloning, dubbing, transcription, and audiobook tools, presented as an alternative to subscription voice services. The hosts emphasize keeping generation on your own computer rather than paying per-use cloud credits; processing still depends on local hardware. 26:54

github.com

Presenter

Community showcase: turns an agent-written presentation into narrated slides and a shareable watch page. The appeal is producing both the explanation and its delivery format from a prompt. 28:26

github.com

Delegate Router

Community showcase: delegates already-defined coding tasks to other models while the lead assistant handles planning and checks the result. The hosts highlight using cheaper/faster models for repetitive work rather than spending premium-model capacity on everything. 28:57

github.com

SHOW Standard

Community showcase: a structured content-rating system for books and stories that separates sexual explicitness, romantic intensity, darkness, and taboo/transgressive content. An accompanying agent skill helps produce ratings, offering more detail than a single broad maturity label. 30:36

github.com

Karpathy Skills Extended

Community showcase: coding guidance with an extra check for consequential missing information. The hosts like an agent asking a useful question instead of confidently implementing a guess. 31:53

github.com

Container

Community showcase: persistent Linux workspaces for agents, keeping their work separate from the host environment. The hosts emphasize limiting the damage an autonomous command could do, rather than giving it unrestricted access to personal files. 32:11

github.com
