Nimrod uses Grok Bot as the voice layer for his existing T3 Code coding agents. He speaks to one bot, one project thread routes the work, and the bot brings questions back out loud. The fast setup gave the bot broad command access; his second setup removes that access from his desktop but still gives a cloud device access to his private network.

Full video captions, non-verbatim video-understanding notes for on-screen details, and Nimrod's companion setup notes. Official pages confirm tool identities; the setup was not run independently.

Key ideas

Start with an existing T3 Code setup and access to Grok Bot voice chat. The video shows Claude Code and Codex as examples of coding agents, not as separate requirements. Nimrod says Grok Bot was the voice option that worked for him in Romania. 0:16 · Grok Bot docs

Use one project thread as the dispatcher. Nimrod calls it the “god thread.” Grok Bot sends requests to that one thread; it starts or messages the workers and routes questions back to him. He says this makes five to ten parallel threads easier to follow. 1:24

Let the agents prepare the change, but keep the final review. His example: improve the aicms newsletter so bounces and spam complaints remove recipients. The bot can ask whether temporary bounces count while other tasks keep running; the on-screen example shows removing permanent bounces immediately and temporary ones only if repeated. Agents open the merge request, address review comments, and prepare a preview; Nimrod checks it himself later. 3:12

First setup: use the T3 command line. Install Grok Bot on the same computer that already reaches your T3 threads, allow it to run commands, and point it at `t3 thread list`, `t3 thread send <id> "message" --wait`, and `t3 thread show <id>`. The desktop app must stay open, and the permission is not limited to T3 commands. That's why Nimrod moved on from this version. 5:25

Second setup: connect the bot's cloud computer to T3 through Tailscale. In T3, turn on **Settings → Sharing & access → Tailscale HTTPS**, then use **Settings → Environments → ⋯ → Copy MCP URL**. In Grok Bot, use **Connect apps → Your plugins → Tailscale → Authenticate**. In Nimrod's setup, tagging the new device disconnected it. 6:03 chapter start

Run the connector on the bot's computer, not as a bare URL. Nimrod used `npx -y mcp-remote@0.16.4 <MCP URL>` as a local connector so it could reach his private network. He ran the same command in the bot's terminal for the first sign-in because the connector timed out after 60 seconds. He completed pairing from a device on his network, got the pairing code under **Settings → Sharing & access** or with `t3 auth pairing create --ttl 5m`, and returned the localhost redirect to the waiting sign-in. **Supervised** could not drive his existing **Full access** threads. He reports 30-day authorization and a revoke option in T3's **Sharing & access** settings. Setup notes

Test with a thread that replies “pong,” then turn off Grok Bot's desktop command access if you enabled it for the first method. Nimrod hoped for a built-in T3 connector; the video does not establish that one exists. 7:09 chapter start · Setup notes

What sold him was hearing replies, not just dictating. He says a two-way conversation lets him keep working away from the keyboard and ask or answer follow-up questions without constantly looking at a screen. That's his experience, not a productivity benchmark. 7:23

Caveats

Nimrod says his cloud device could reach other devices on his Tailscale network, not just T3. He had not found a supported way to narrow that access in his setup. Access caveat in his notes

The `mcp-remote` version in the creator's notes is historical, not a current recommendation. Version 0.16.6 added security fixes that his 0.16.4 pin lacks.
